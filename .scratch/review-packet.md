## 1. 這個專案在做什麼

一個人（非醫學專業、看不懂英文論文）想用系統性文獻回顧的方法，
回答自己的健康問題。做法是：把「什麼算證據」寫成機器看得懂的契約，
先凍結契約再讀論文，讓判定盡量由確定性程式碼做，模型只負責讀。

設計原則是 **fail-closed**：不確定就擋下來，**寧可停住也不要安靜地產出東西**。

## 2. 原本的計畫（兩份決策紀錄，2026-08-14 拍板）

**ADR-0010（里程碑與委任）**
- 營運決策委任給協調者；擁有者的接觸點是里程碑。
- **M1 =「B.11 校準集就緒」**＝篩選走完（含統計終止證據）→ 60 篇校準集依
  strata 抽出 → 開放取用全文取得 → **首輪抽取跑通，附品質報告**。
- 契約級變更（凍結物升版）仍屬擁有者。

**ADR-0011（領域路線圖）**
- **B.11（運動中碳水補給／耐力）只是校準場**，與擁有者的健康需求幾乎無關；
  做到 M1 為止，不繼續走向該領域的結論。
- 真正的目標依序是：**P1 減脂期蛋白質與肌肉保留**（服務「−18.5 kg 脂肪、
  肌肉不減」）、**P2 睡眠**、**P3 壓力性進食**、**P4 肌酸與咖啡因**（可並行）。
- **M2 = P1 領域的首批 AI 分級證據。**
- 原本「140 個領域全做」的野心已判定不可行（估 2.7 人年），降為背景清單。

## 4. 我們自己知道的問題（不要客氣，請你補充我們沒看到的）

1. **抽取的正確性，直到昨天都沒有任何東西在看。** 鏈上每一道檢查守的都是
   「格式對不對、綁對了沒」，**一份格式正確、內容讀錯的清單會一路通過。**
2. **第二位讀者上線第一天就抓到一個真缺陷**：判定程式拿「儀器名稱」逐字比對
   契約的允許清單，**而讀的人從來沒被告知那份清單**，於是自己編了描述性名字，
   六項全部以「儀器不在允許清單」被排除——**那篇論文用的其實就是允許的儀器**。
   十七篇裡唯一做肌肉切片的那篇，因此整篇不貢獻任何東西。已修，但**已讀的
   23 篇拿到的是修改前的請求**。
3. **兩位讀者的結局標籤零逐字重疊（41 對 18）**，差在顆粒度不在實質：
   一邊把血漿代謝物拆成十筆、一邊記成一筆。**兩邊都不算錯**，
   但「這篇論文報告了幾個結局」因此完全取決於誰讀的。
4. **P1 的契約有三項判準，現行 schema 容不下**（訓練狀態不得合併、
   蛋白質劑量的分母有兩種、兩組的熱量赤字必須相當），目前只寫在散文裡，
   **沒有任何機器在強制**。
5. **P1 的候選池有多大，完全不知道**——那是工時估計裡最大的未知數，
   而它只要跑一次搜尋就能便宜地量出來（但搜尋契約要先凍結，那是擁有者的事）。
6. 有一層 RDF／SHACL 檢查在本機根本跑不起來（套件沒裝），
   **等於那一層目前形同不存在。**

## 5. 請你回答這幾題（不用全部答，挑你有把握的）

1. **B.11 這個校準場，是不是已經達成目的了？** 它與擁有者的健康需求無關，
   而 M1 定義要求它「首輪抽取跑通」。**現在已讀 23／41 篇。
   繼續讀完剩下的，值不值得？還是應該提早收手轉去 P1？**
2. **順序 P1 → P2 → P3 → P4 合理嗎？** 以「減脂保肌」為首要目標的話，
   有沒有哪一個應該提前、或根本可以不做？
3. **兩位讀者的一致性，該怎麼量才有意義？** 逐字比標籤顯然不行
   （顆粒度不同）。系統性回顧領域對「雙人抽取的一致性」有沒有標準做法？
4. **這種規模的系統性回顧，我們有沒有漏掉必須做的步驟？**
   （例如：偏誤風險評估、計畫書預先登錄、PRISMA 流程圖、
   發表偏誤檢查——這些我們目前都沒有明確在做。）
5. **看下來，哪一部分的工夫最可能白費？** 擁有者最在意的是時間。
