# ADR-0005：精確品質閘門與契約凍結的前置檢查

- 狀態：已接受
- 日期：2026-08-13
- 情境：v2 用 rule-of-three 近似式做品質閘門，且契約凍結沒有前置檢查

## 問題一：近似式比精確式嚴格

v2 的 SHACL shape 用 rule-of-three（`3/n`）估計零錯誤下的錯誤率上界。
實測時 **n = 299 被自家的 shape 否決**：

| n | rule-of-three `3/n` | Clopper–Pearson 精確 |
|---:|---:|---:|
| 30 | 10.00% | 9.5034% |
| 60 | 5.00% | 4.8703% |
| 299 | 1.0033% | **0.9969%** |

299 是精確計算下達到 1% 上界的最小樣本數，但近似式算出 1.0033% > 1%，
於是把正確答案擋掉了。

更根本的問題是**分工錯置**：SHACL 不該做統計計算。它該驗證的是「用了哪個
方法、輸入是什麼、計算 provenance、pass/fail 結果」，不是重算一次。

## 問題二：契約可以凍結成無解狀態

範圍契約凍結後就成為所有 StudyResult 的 provenance 依據。但 v2 的凍結沒有
任何前置檢查，所以可以凍結出一份**任何資料都無法乾淨通過**的契約：

兩個 in-scope 時窗重疊時（例如 3–6 週與 5–8 週），任何落在交集的測量點都會
同時命中兩個窗，被 `SCOPE-002b` 升級為人工裁決。這不是資料品質問題——是契約
作者的錯誤，而且在凍結前就能確定性檢出。放行的代價是跑完整批文獻後才發現
一半的結果卡在人工佇列。

劑量分帶重疊與重複 ID 是同一類問題：前者讓比對結果取決於清單順序，後者讓
`matchedScopeElements` 無法回指唯一定義。

## 決策

### 品質閘門

**Clopper–Pearson 精確計算由 Python gate 負責**（`stats.beta.ppf`）。
SHACL 只驗證方法標籤、輸入與結果，不重算。邊界測試釘住
n=30 → 9.5034%、n=299 → 0.9969%。

**`insufficient-evidence` 是獨立於 pass/fail 的第三種結果。** 缺 gold
（accuracy / major error / common-wrong 任一為 None）或 AC1 缺
`modelAssumptions` 時，回傳 `insufficient-evidence` 而不是 fail。
「沒有證據」與「證據顯示不合格」是不同的狀態，混為一談會讓人以為補資料
就能翻案，或反過來以為不合格只是資料不全。

**AC1 結果標明假設。** 明確寫成「在指定 prevalence、獨立等誤差模型與搜尋
網格下的估計」。`None` 的意思是「在所測網格內未達門檻」，不是「永遠達不到」——
`sampling_power.json` 因此帶 `search_grid_max` 與 `not_reached_within_grid`。

**不為湊數新增檢查。** v2 文件宣稱 16 項確定性檢查，實作是 13 項。決定是
讓文件服從實作：忠實宣稱 13 項，保留 008–010 的 ID 空缺，日後有方法學依據
與實際需求才新增。反過來做（補三個湊數的檢查）會讓「16」這個數字失去意義。

### 契約凍結

**雜湊排除雜湊欄位自身。** 否則寫回雜湊會改變被雜湊的內容，沒有任何一份
已凍結的文件能通過自我驗證。

**草稿與產物分離。** `scope-contract.draft.json` 是可編輯來源，
`scope-contract.json` 是 `freeze_contract.py` 的產物。手改產物會讓雜湊失效，
`test_contract_is_frozen_and_hash_self_verifies` 會抓到。

**凍結前跑確定性前置檢查**（`freeze_preflight`）：時窗重疊（含跨單位比較、
邊界相接、session 與時間分開判斷）、劑量分帶重疊（同單位才比較）、重複 ID。
任一不通過就整個中止，不寫出半成品。

**交叉引用釘住雜湊。** `strata.json` 記錄它所依據的 `scopeContractHash`。
契約改版而抽樣框沒跟上時，兩份檔案各自都合法——只有交叉比對抓得到。

## 後果

- SHACL shapes 變薄，Python gate 變厚。統計正確性集中在有測試的地方。
- 改契約要重跑凍結腳本，不能手改。多一個步驟，換來雜湊永遠可信。
- `insufficient-evidence` 讓「還沒測夠」無法被誤讀為「測過了不合格」，也無法
  被誤讀為通過。
