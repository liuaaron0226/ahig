## 一、🚫 全節第一禁令：**不得寫成「這些主題文獻少」**

看板 63655 原句，須照抄：

> **🚨 OA 取得管道在「本契約最在意的結局」與「機轉層」上最不管用。**
> **⚠️ 不得寫成「這些主題文獻少」——文獻存在，是付費牆後。**

**⚠️ 兩者在讀者端是完全不同的結論**：
「文獻少」講的是**這個領域的性質**；
「拿不到」講的是**我們的取得管道的性質**。
**🚨 把後者寫成前者，等於用自己的取得限制去描述世界。**（檢查表第十二條同源。）

### 🚨 但本節有**兩個不同的「拿不到」**，其成因相反，不得混寫

| 母體 | 筆數 | 為何拿不到 |
|---|---|---|
| **缺口** | `{{SHORTFALL_N}}` | **不在 OA 之內**——上句之「付費牆後」說的是這一批 |
| **遭擋** | `{{BLOCKED_N}}` | **在 OA 之內**，但出版社擋自動化抓取（見第三之二節） |

**⚠️ 兩者若混寫，會得到一句兩頭都不對的話**：
把遭擋者說成付費牆，低估了可補救性；把缺口說成「只是被擋」，高估了可補救性。
**🚨 這是本 run「同型」家族之延伸：不只數字要分母體，成因也要。**

**🚨 關鍵事實（讀原始碼確認，非推測）**：本批 45 筆全部取自**開放取用**位址——
`fulltext.py` 第 843 行取 OpenAlex 之 `best_oa_location`，

**🚫 三條界線**：
1. **不得以重試硬闖**；
2. **禮貌抓取（具名 UA、節流）可試，但那是降低被誤判為機器人的機率，
   🚨 不是繞過阻擋**——出版社若明示拒絕自動化存取，即停止；
3. **本節一律寫「本環境連不到」，🚫 不得寫「文獻取不到」**——

## 三之三、🚨 **在手的不一定是「刊出的那一版」**

**⚠️ 這一節是全辛節對結論影響最大的一項，而它到第 485 輪才被看見。**

同一篇論文在網路上通常有三種版本：

| 版本 | 是什麼 | 對數值的意義 |
|---|---|---|
| `publishedVersion` | **期刊刊出的那一版** | ✅ 讀者查得到的就是這個 |
| `acceptedVersion` | 審查通過、但**尚未排版校對**的作者稿 | **⚠️ 數據、圖表、討論仍可能與刊出版不同** |
| `submittedVersion` | **投稿當時的稿**，尚未經同儕審查 | **🚨 連審查意見都還沒回應過** |

**⚠️ 全部 `{{ACQ_ALL}}` 筆 acquired manifest 已查完**（分兩批，母體互斥）：

| 版本 | 筆數 |
|---|---|
| `publishedVersion` | `{{VER_PUBLISHED}}` |
| `acceptedVersion` | `{{VER_ACCEPTED}}` |
| `submittedVersion` | `{{VER_SUBMITTED}}` |
| **🚨 版本不明** | `{{VER_UNKNOWN}}` |

> **🚫 版本不明一律不得計入 published**——⚠️ 那會把「沒查到」寫成「查到是好的」。

### 🚨 而這一格曾經一度是 26，那個 26 誤導了兩則裁定

**⚠️ 補查之前**，版本不明有 26 筆，於是 n+140 得出「確認為刊出版者僅 5 筆」。
**🚨 補查之後（PMCID → DOI 反查）：25 筆全部是 `publishedVersion`，1 筆仍不明。**

> **🚨 「不明」不是壞消息，是量測缺口——而該缺口不是隨機的。**
> **⚠️ 26 筆全部集中在同一條取得路徑**（Europe PMC 以 PMCID 取得，
> 從未留下書目庫查詢），**而那條路徑取回的恰恰全是刊出版。**

**✅ 正確的一般規則有兩條，缺一不可**：
1. **🚫 不明不得計入 published**（fail-closed，n+140 這一半是對的）。
2. **🚫 不明也不得反過來當成「多半是作者稿」的證據**——
   **🚨 那是把量測缺口當成量測結果。**

### ✅ 非刊出版集中在哪：**整批落在 PDF／典藏庫那條路**

| 取得路徑 | 刊出版 | 作者稿（accepted／submitted） |
|---|---|---|
| Europe PMC（出版社寄存之 JATS） | **全部** | **0** |

> **🚨 故「手上有作者稿」這件事有明確範圍**——**它只發生在新開的那條路上。**
> **⚠️ 而那正是本 run 為了補足缺口才走的路。**

### ✅ 裁定之處置（n+138）

| 版本 | 可否作為數值萃取來源 |
|---|---|
| `publishedVersion` | ✅ 正常萃取 |
| `acceptedVersion` | ✅ 可萃取，**⚠️ 但每一個取自作者稿之數值須逐筆標記**，🚫 不得與刊出版數值並列而不區分 |
| `submittedVersion` | **🚫 不得作為數值來源**；可用於確認納入與定性描述。**⚠️ 若尋不到 accepted 或 published 版，該筆列為「有全文而數值不可用」並如實計入殘量** |

**🚨 理由**：本 run 的讀者查不了英文文獻，**他無法自行發現「報告裡的數字不在期刊那一版裡」。**
**⚠️ 這種錯一旦發生，沒有任何下游檢查抓得到。**

**⚠️ 併記一項不得誇大的界線**：`submittedVersion` **不代表該研究未經同儕審查**
——**研究本身已刊出，只是我們手上這份是投稿稿。**
**🚨 危險不在研究的地位，而在「我們讀到的數字未必是刊出的數字」。**

### 🚫 三個不得說的句子（各有其誤導方向）

| 🚫 不得寫 | ⚠️ 因為 |
|---|---|
| 「**已萃取**」 | 在手＝有可用節與偏移，**萃取是下一步，還沒做** |
| 「這是**可得數**」 | 在手數是**已取得**者；可得數是另一個更大的上界，**兩者不是同一個量** |
| 「**取得問題已解決**」 | 工具裝好、驗收通過、登錄完成，**⚠️ 三件都不等於「該拿的都拿到了」**——遭擋者仍有未動的 |

**🚨 這三句的共同點**：**它們都在把「某一步做完了」講成「這件事做完了」。**

### ⚠️ 引用 TEI 產出之數值，須併記產生它的版本

**🚨 只記 TEI 的雜湊不足以重現**——**同一份 PDF 經不同版本的解析器會切出不同的節。**
**✅ 故凡引用自 TEI 之節數、字元數或偏移，須併記 `grobidVersion`**
（本批為單一版本，🚫 但不得因此省略；下一批可能不同）。

**⚠️ 與三之三之版本欄不可混淆**：那一欄講的是**文獻本身是哪一版**
（刊出版／作者稿），**本項講的是我們的解析器是哪一版。🚨 兩個「版本」不同義。**
