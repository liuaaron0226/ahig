# ADR-0009：信任模型修訂——AI 判讀證據、擁有者稽核

- 狀態：已接受
- 日期：2026-08-14
- 情境：專案擁有者確認自身不具領域專業、無法閱讀英文文獻；原設計中所有
  「人類專家判讀」環節（篩選、劑量判讀、gold set、裁決）的執行者不存在。
  本 ADR 部分修訂 ADR-0007/0008 的人類前提

## 問題

AHIG 的信任基礎原是 `requiresHumanScreening=true`：機器只排序與提示，
判斷由人類專家做。實際情況是專案沒有這位專家——擁有者的角色是系統擁有
者與稽核者，不是文獻判讀者。可選的路：

- **A. 降低任務門檻讓擁有者判讀**（翻譯輔助＋速查表）：對「找數字」級
  任務可行，對 15,425 篇的篩選與全文抽取不可行。
- **B. 正式修訂信任模型**：AI 判讀、完整留痕、擁有者抽查（採）。
- **C. 引入外部人類專家**：目前無此資源；若未來出現，本 ADR 可被再修訂。

## 決策

採 B，五條原則：

1. **產出重新定位**。AHIG 的證據產出定位為「**AI 判讀證據，供擁有者個人
   使用**」。任何報告、Claim、匯出物必須帶明顯標示：
   `AI-graded evidence — no human expert review`。在此標示下這是誠實的
   系統；冒充人類專家審過才是不誠實。
2. **每筆判斷記錄判讀者**。所有含判讀的 artifact 新增 `judgedBy`
   欄位（`human` 或 `llm`＋模型與版本）。缺此欄位的判讀不得進入任何
   下游計算。
3. **AI 判讀的留痕要求沿用 ADR-0007**：prompt、模型版本、原始回應、
   時間戳全部落盤入雜湊鏈；模型或 prompt 換版視同重要事件。
4. **擁有者抽查取代專家覆核**。每批 AI 判讀，擁有者以翻譯輔助抽查
   固定比例（初始 10%，可依實測調整），抽查結果留檔；抽查發現系統性
   錯誤時該批判讀作廢重跑。抽查任務必須降到「找數字、對關鍵詞」層次。
5. **高風險環節用多模型冗餘**。critical harms（GI 症狀）與安全分支的
   判讀至少兩個獨立模型盲判，歧異提交擁有者抽查佇列——原「人類雙盲」
   的位置由「雙模型盲判＋擁有者裁決」接替。

對 ADR-0007/0008 的影響：

- ADR-0007 的「人單審全量」改為「主模型判讀全量＋第二模型盲判」；影子
  批次的門檻邏輯保留，但比較對象從人-機改為機-機＋擁有者抽查。
- ADR-0008 的統計終止不受影響（它本來就不依賴誰在判讀），但終止後尾端
  抽驗改由擁有者以翻譯輔助執行（「這篇有沒有可能相關」的粗判）。
- `requiresHumanScreening` 欄位語意更新：human 指「擁有者稽核迴路」，
  不再暗示逐篇人類專家判讀。invariant 改述為
  `ai-graded-owner-audited-never-silent`。

## 理由

1. 假裝有人類專家（實際由不具能力的人硬填）比 AI 判讀更不可信；B 是
   把系統實際能提供的信任水準誠實寫在標籤上。
2. 2024–2026 的實證（見 ADR-0007 引註）顯示 LLM 判讀在題摘層與人類
   專家的一致性已可比較；本專案的用途（個人決策輔助）承受得起殘餘
   誤差，前提是標示誠實、留痕完整、抽查持續。
3. 擁有者抽查不是儀式：它是「找數字」級的任務，恰好落在擁有者能力
   範圍內，形成真實的（而非表演性的）人類監督迴路。

## 後果

- 立即適用：prevalence audit `22f634d2325d` 的 62 筆判讀由 LLM 執行
  （judgedBy=llm），estimate 輸出帶 AI 判讀標示；擁有者抽查其中 6 筆。
- 篩選階段開跑前需把 ADR-0007 的影子批次改為機-機版本（實作待排程）。
- 工時模型翻轉：原 387 小時人工牆改為 API 成本＋擁有者抽查時數（估
  每批 1–2 小時），`human_throughput.py` 的重校準需反映新模型。
- 專案對外可信度天花板明確降低：若未來要供他人使用或發表，必須引入
  真人類專家並再修訂本 ADR——這個限制寫在這裡，不藏。
