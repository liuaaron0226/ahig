# ADR-0002：互動只做內建捲動，不做自然語言翻譯層

- 狀態：已接受
- 日期：2026-07-31
- 情境：`/watch-ui` skill 設計

## 問題

錄影期間必須對頁面做些什麼，否則錄到的是靜止畫面。如何描述這些互動？

- **A. 內建捲動**：唯一動作是從頂端平滑捲到底，使用者不需描述任何互動。
- **B. 自然語言翻譯**：使用者寫「捲到定價區、hover 第二張卡」，即時翻譯成 Playwright 程式碼。
- **C. 使用者自備腳本檔**。

## 決策

採 A，並保留「直接餵現成影片檔」作為逃生門。

## 理由

1. **素材本身給出答案。** `bixlink-sodium-site/index.html` 有 24 處 GSAP 呼叫，配合 ScrollTrigger。捲動一個動作即可觸發此類網站絕大多數動畫。

2. **B 的隱藏成本高。** 自然語言轉 selector 需先 snapshot 頁面、猜 selector、猜錯重試。一個「錄 15 秒影片」的操作會膨脹成多輪往返，且不穩定。

3. **C 把工作推回使用者。** 每次驗證前先寫腳本，會導致工具實際上不被使用——與 `/watch-ui` 存在的目的（降低驗證摩擦）相衝突。

## 後果

- hover、點擊、拖曳等互動不被自動涵蓋。這類情境走逃生門：使用者自行錄影後餵入。
- 需提供 `--duration` 調整捲動時長，因為動畫節奏因站而異。
- 捲動必須「平滑」而非跳躍，否則 ScrollTrigger 的 scrub 動畫會被跳過。

## 已考慮但未採用

B 在「hover 效果驗證成為高頻需求」時值得重新開啟。屆時應以本 ADR 為起點評估，而非直接推翻。
