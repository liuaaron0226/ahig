# ADR-0013：P1 的主問題改為「減多快才不掉肌肉」

- 狀態：已接受（擁有者 2026-08-31 選甲）
- 日期：2026-08-31
- 取代：ADR-0012 決策 1 之問題框架（🚫 其方法學底線各條不變）
- 情境：擁有者指出蛋白質不是他的主要問題。其所持理由（InBody 的蛋白質讀數
  高於平均）**不成立**——那是身體組成的隔間而非攝取量，且 InBody 屬生物電阻，
  本案自己的契約已將其降為 supporting。**但其結論另有理由成立**：外部審視
  已指出減重速度與阻力訓練在因果上都在蛋白質上游

## 決策

1. **P1 之暴露由「每日蛋白質攝取量」改為「減重速度」**，
   分段為每週佔體重百分比：`slow` 0–0.5、`moderate` 0.5–1.0、
   `fast` 1.0–1.5、`very-fast` 1.5–3.0 %BM/week，各段分開產出結果。
2. **蛋白質降為必要共變項**：仍須報告，且未報告者排除。
   **沒有它就分不出肌肉流失是速度造成的還是蛋白質不足造成的。**
3. **比較的匹配條件反轉**：舊契約要求「比較蛋白質時兩組赤字須相當」；
   現在比較的就是赤字，故要求變成**「兩組的蛋白質與訓練須相當」**。
4. **目錄更名** `p1-protein-deficit` → `p1-deficit-rate-muscle-retention`。
   名稱與內容不符是本案反覆吃虧的那一型，不留一個以舊主問題命名的目錄。
5. **不可表達之判準由五項變四項**，且其中一項反轉——見
   `scope-extensions-required.md`。

## 理由

擁有者的目標是「−18.5 kg 脂肪、肌肉不減」。在那個目標下，
**他每天能決定的是掉多快與練不練，蛋白質是第三順位的旋鈕。**
把第三順位的旋鈕當成主問題，得到的答案即使正確也不好用。

一項附帶發現值得記下：`stratifyByDeficitMagnitude` 先前列為
「schema 表達不出來」，**而換了主問題之後它自己就可以表達了**——
因為 `doseBands` 加 `separateStudyResultPerDoseBand` 說的正是這件事。
**schema 表達得出什麼，取決於什麼被選為暴露。**

## 後果

- P1 開工順序不變（ADR-0012）：review-of-reviews → 搜尋契約 → 池子估算
  → 範圍契約 → 凍結。**⚠️ 但 review-of-reviews 要找的題目換了**：
  要盤點的是減重速度與肌肉保留的既有回顧，不是蛋白質劑量的。
- 蛋白質仍會被抽取，故日後若要回頭問蛋白質那一題，資料是現成的。
- 擁有者另稱「現在連減脂都不順利」（原文為同音之「剪紙」，本案據上下文如此理解；
  🚫 若理解有誤請更正）。**⚠️ 那句話與本 ADR 的問題不必然是同一件事**：
  「掉不下去」「掉了但掉到肌肉」「維持不住赤字」是三個不同的問題，
  各自指向不同的領域（前者未立案、次者即本 P1、末者為 P3）。**待其澄清。**
