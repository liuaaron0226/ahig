## 一、抽查債帳本

### 🚨 交付前必須先解決的一件事：「17 筆」是三個來源相加，而**從未驗證互斥**

看板第 24 輪記載：

**⚠️ 這正是檢查表第四條所禁的形態**：**兩個以上來源的筆數直接相加，
未先取聯集去重、未聲明是否重疊。**

**⚠️ 而本 run 已有前例證明這種加法會出錯**：全 queue 未篩數曾以同樣方式
得出 5,357，實為 5,115，**且兩個錯互相遮蔽——只修其中一個會得到 5,057，仍然是錯的**。

**判斷之現況（如實陳述，不逾越證據）**：
三個來源**看起來**分屬不同批次——W2 補抽為批次 `0030677e77bf`；
影子歧異筆出自 300 筆影子對帳，而影子樣本**依設計不在主工作單內**；
pilot 為第三來源。**⚠️ 但「看起來分屬不同批次」不是驗證。**

**交付時必做**：**逐筆取三份 candidateId 清單、求聯集、報去重後之數**。
- 若確為互斥 → 記為 `{{DEBT_OUTSTANDING}}`，並註明**已驗證互斥**。
- 若有重疊 → **重疊筆數與其成因須一併載明**，不得只更正總數。

## 四、流程品質之陳述（供擁有者判斷可信度）

擁有者非領域專家（ADR-0009），**信任建立在流程留痕上**，
故本節須如實包含**不利於執行方之紀錄**：

- 參數是否事後調整（**否**，兩次觸發之間未動）
- 絆網是否真的攔過（**是**，第一次觸發即被攔下並作廢）
- 執行室自曝之錯誤（含一次**自行推翻對自己有利的科學主張**）
- **協調者自身之錯誤**（含裁定漏推主幹、誤記未落實、誤讀檢查涵蓋範圍、
  以及一道**若照辦會弄壞凍結證據**的指示被執行室拒絕）
- 驗證器攔截之案例（**一條抄錯的清單原將以「五筆全文優先清單」交到擁有者手上**）

**⚠️ 這一節不得寫成自我表揚**：其價值在於**列出被攔下來的錯**，
而不是宣稱沒有錯。**🚨 一份沒有錯誤紀錄的流程報告，讀者無從判斷它有沒有在檢查。**
