# 丙：什麼時候停止篩選，以及憑什麼說可以停

**產生時刻：2026-08-30 09:17 UTC**　（⚠️ 本節數字於產生當下由權威來源現算，🚫 未沿用任何一輪之值）

> **這一節怎麼讀**：每一小段的第一句話是結論，用日常語言寫的。接在後面的是給稽核者查證用的依據。**只讀第一句，也能讀完整節。**

---

## 一、我們沒有一路篩到底，而這是事先講好的

**一句話**：文獻有九千多篇，我們篩了七千多篇就停下來。停下來的條件是**在開始篩之前就訂好的**，不是篩到一半覺得夠了才訂的。

判斷用的是一種序列檢定：每篩一批就算一次「還漏著重要文獻的機率」，低到事先訂的線以下才可以停。三個參數在正式開篩前就凍結：

- 顯著水準 α ＝ **0.05**
- 目標召回率 ＝ **0.95**
- 尾端抽驗筆數 ＝ **200** 筆

**⚠️ 「事先訂好」這件事本身需要證據，否則等於沒訂。**這三個參數的依據是一場事前的模擬實驗：

在 **2270** 條模擬路徑上，隨機情境下的違反率是 **0.0115**，刻意找碴的對抗情境下升到 **0.3652**；而尾端抽驗在對抗情境下的攔截率是 **0.8893**。

> **這一段是整節可信度的根**：參數不是事後挑出來讓結論成立的，而且兩次觸發之間一次都沒有調整過。

## 二、這個結論管到哪裡為止

**一句話**：這個統計結論只涵蓋主線的那一批文獻，**其他幾條線不在裡面，而那是設計，不是漏掉。**

> **本統計涵蓋宣稱僅及於標準線之 9,091 筆。**
> `animal-signal-review`、`review-source-review`、`registry-review`、`identity-review`
> **各 lane 由確定性路由處置，不在本統計宣稱範圍內**，
> **其未篩狀態是設計使然，且永久保留可稽核。**

**為什麼分母是這一批而不是全部**：這一批的數目是閉合的——

已篩 **7431** ＋ 亂序 **200** ＋ 未篩 **1460** ＝ **9091**

> ⚠️ 這裡的「亂序 200 筆」與第一節的「抽驗 200 筆」剛好是同一個數字，**但它們毫無關係**：前者是排序之外被判掉的紀錄數，後者是事先訂好的抽樣張數。🚨 這兩個數一起變動的理由並不存在。

三個數相加分毫不差，且第一次觸發當時凍結下來的數值**只有在這個分母下才重現得出來**。

> **⚠️ 範圍有界，不等於結論可疑。**上面那句話說的是「這個結論及於什麼」，🚫 不是「這個結論站不住」。

## 三、停止的條件其實達成過兩次，而兩次不是同一件事

**一句話**：第一次達標後我們去抽驗，抽到了東西，於是**作廢重篩**；第二次達標後抽驗沒抽到，才真的停。

| | 第一次 | 第二次 |
|---|---|---|
| 觸發點 | 判到第 279 頁 | 一筆紀錄改判所致 |
| 機率值／視窗 | `0.046023`／177 | `0.012404888703091584`／201 |
| 抽驗母體 | 2116 筆 | 1460 筆 |
| 抽驗命中 | **2 筆** | **0 筆** |
| 結果 | **終止作廢，恢復篩選** | 終止維持 |

（白話說：兩次的機率值都低於事先訂的 0.05——第一次約 4.6%，第二次約 1.2%。）

> **⚠️ 上表兩個機率值的位數不一樣，那不是排版失誤。**兩者都是**凍結值**，各自照它被凍結當下的樣子引用；**🚫 為了好看而把其中一個四捨五入，就是改動凍結證據。**上面那句白話的百分比是**另外算給人讀的**，🚫 不得反過來當成被引用的值。

**⚠️ 兩次的成因型態不同，🚫 不是同一件事重測一遍。**第一次是判讀一路推進而自然達標；第二次是**一筆紀錄由「看不出來」改判為「排除」**，這個改判把統計視窗從 115 併成 201，於是達標。

（兩次相隔 20 頁。**⚠️ 頁距只是佐證**——成因型態的差異不依賴用哪一種頁數口徑來數。）

### ⚠️ 而上表「抽驗母體」那一列，兩邊的算式其實不一樣

表格會讓人以為那是同一種量在變小。**不是。**

```
第一次   9091 − 6,975                 = 2116   （兩項式）
第二次   9091 − 7431 − 200   = 1460   （三項式）
```

**成因**：算式裡的第三項（亂序）是第一次觸發**之後**才設立的類別。第一次觸發的時候，它還不存在。

這段歷史在三個地方留下痕跡，且三者都不是錯誤：

| 痕跡 | 第一次 | 第二次 |
|---|---|---|
| 證據雜湊的原像欄位數 | 11 欄 | 12 欄 |
| 抽驗母體的算式 | 兩項式 | 三項式 |
| 整份文件的自證雜湊 | 有 | 無 |

### 第一次被攔下來，該怎麼理解

**絆網比檢定更嚴，兩者都照設計運作。**

> **🚫 這件事不是「統計判斷錯了，被抽驗糾正」。**檢定負責判斷何時可以停，抽驗負責在停之前再確認一次；抽驗攔下來，正表示這道設計有用。

**⚠️ 還有一件事必須說清楚，否則會被當成額外的保證**：第二次抽驗的母體與第一次**零重疊**——**而那是由建構必然如此**（第一次已判過的必然不在第二次的母體裡）。**🚫 故它不能被引為「已經獨立覆核過兩次」。**

## 四、這些數字別人查得到嗎

**一句話**：查得到。證據鏈六步都留了檔與雜湊，而且我自己重跑過一次抽樣，抽出來的完全一樣。

**協調者之獨立覆核**：自版控內的母體清單重跑抽樣程式，所得 **200** 筆與凍結產物**逐位相符、順序相同**，種子由錨定雜湊確定性導出。

**六步證據鏈之雜湊已逐一定位**：自證 10 個皆重算重現，引用 16 處皆與上游同值。**唯一無法自版控重現者**為工作單雜湊——其原像是工作單檔本身，屬外部錨。

**⚠️ 引用雜湊時必須寫明它涵蓋什麼範圍。**實測共有五種涵蓋範圍（整份文件／子物件原樣／清單本身／固定欄位原像／本檔內容加上游雜湊），**🚨 只寫欄位名而不寫範圍，稽核者要在五種裡面猜。**

> **⚠️ 而這一節的效力來自產物本身可重現，🚫 不是來自腳本寫得對。****程序正確不等於產物正確**——能證明程式沒寫錯，不能因此宣稱某一次跑出來的東西沒錯。

## 五、這一節的限制

**⚠️ 以下四點都是主動寫出來的，🚫 不是被問到才承認。**

1. **抽驗沒抽到，不等於沒有漏。** 正確讀法是「在隨機抽出的 **200** 筆裡沒有發現相關文獻」，🚫 不是「剩下的都不相關」。未篩的紀錄永久保留，隨時可以再抽查。

2. **工作單依相關性排序，這會讓機率值偏向樂觀。** 檢定假設視窗是隨機抽樣，而實際上不是。事前模擬中對抗情境的違反率 **0.3652** 即這個偏差的量級，**尾端抽驗就是為了補償這個偏差而設。**

3. **涵蓋範圍有界**（見第二節）——**而範圍有界不等於結論有疑。**

4. **未篩數的來源必須聲明。** 本次有六個判讀來源，**漏掉任何一個，這一節的五個數字會全部錯。**
