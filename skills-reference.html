01開發流程

寫程式前中後各階段該接哪一棒，避免跳過需求釐清或驗證就直接動手。

brainstorming

做任何新功能/新元件前先釐清使用者意圖、需求邊界與設計方向。 用於：「我想做 X」這類創意起點，動手寫之前。

writing-plans

已有明確需求，寫成分步驟的實作計畫。 用於：多步驟任務要開新 session 執行前。

executing-plans

依照已寫好的計畫逐步執行，中途設審查檢查點。 用於：計畫已定案，要在獨立 session 落地。

test-driven-development

先寫測試再寫實作。 用於：任何新功能或修 bug 之前。

systematic-debugging

遇到 bug、測試失敗或行為異常時，先系統化定位根因再動手修，而非猜測式修補。 用於：提出修法之前。

requesting-code-review

完成任務或大功能後主動請求審查，核對是否符合需求。

receiving-code-review

收到審查意見時要求實證與技術嚴謹，不盲目照做，尤其意見含糊或技術上可疑時。

verification-before-completion

宣稱「完成/修好/測試通過」之前，強制先跑驗證指令並確認實際輸出。 用於：commit 或開 PR 之前。

using-git-worktrees

開始需要獨立工作環境的功能開發時，建立 git worktree 隔離。

finishing-a-development-branch

實作完成、測試都過後，決定要 merge、開 PR 還是清理分支。

dispatching-parallel-agents

面對 2 個以上互不依賴的任務時，平行派工給多個 agent。

subagent-driven-development

在目前 session 內，用子 agent 執行計畫中彼此獨立的任務。

02審查與精簡

針對「這段程式碼寫得好不好」的各種角度審查，含正確性、過度工程、安全性三條主線。

code-review

審查目前 diff 的正確性 bug 與可精簡之處，依 low/medium/high/ultra 力度調整覆蓋範圍；--fix 可直接套用修正，ultra 會啟動雲端多 agent 深度審查（需另外付費觸發，我不能自動幫你啟動）。

simplify

只做重複利用/精簡/效能面向的審查，找到問題直接套用修正，不找 bug。

security-review

對目前分支的變更做安全性審查（OWASP 類漏洞等）。

review

審查一個 GitHub PR（跨遠端），本機 diff 請改用 code-review。

ponytail

強制採用最簡單能動的寫法：能刪就刪、優先用標準庫/原生功能，拒絕未被要求的抽象層。 用於：任何寫/改/審查程式碼的場合，或你抱怨「太肥、太複雜」時。

ponytail-audit

對整個 repo 做過度工程健檢，列出可刪除/簡化/改用標準庫的清單（不動手改）。

ponytail-review

只針對 diff 抓「過度設計」，如重造標準庫輪子、非必要依賴、投機性抽象。

ponytail-debt

彙整程式碼中 ponytail: 註記的刻意捷徑，做成技術債清單，避免「以後再說」變成永遠不做。

ponytail-gain

顯示 ponytail 模式帶來的效益指標（少寫多少程式碼、省多少成本）一次性看板。

ponytail-help

ponytail 全部指令與模式的速查表。

03設計與前端

從品牌識別、UI 元件到資料視覺化的設計類技能。

design

大型整合設計技能：品牌識別、Design Token、Logo（55 種風格）、企業識別系統（50 項交付物）、HTML 簡報、Banner（22 種風格）、Icon、社群圖片產出，一站式。

design-system

建立三層 Token 架構（primitive → semantic → component）、CSS 變數、元件規格書，以及依此系統產出簡報。

ui-styling

用 shadcn/ui（Radix + Tailwind）打造可存取、風格一致的 UI 元件，含深色模式。

ui-ux-pro-max

UI/UX 設計知識庫：67 種視覺風格、161 組配色、57 組字體搭配、25 種圖表、21 種技術棧（React/Vue/SwiftUI 等），用於規劃、審查、修正介面程式碼。

banner-design

設計各平台（FB/IG/YouTube/LinkedIn/Google Display 等）的廣告與活動橫幅。

brand

品牌語氣、視覺識別、訊息框架、素材一致性管理。

dataviz

建立任何圖表/儀表板前必看，統一色彩與視覺語言，含亮/暗主題配色驗證器。

artifact-design

Artifact 頁面本身的設計方法論（我剛才產出這頁時用的就是這個）。

impeccable

前端介面的深度審查與重新設計：資訊架構、可存取性、排版、色彩、動效、UX 文案等全方位優化。

08瀏覽器與應用操作

實際操作瀏覽器、跑起你的專案、或看影片理解內容。

claude-in-chrome

操作你目前開著的 Chrome：點擊、填表、截圖、讀 console log、瀏覽網頁。使用任何 mcp__claude-in-chrome__* 工具前都要先呼叫這個。

run

啟動並在真實環境中跑你的 app，驗證修改真的有效，而不只是測試通過。

watch

看一段影片（URL 或本機檔案），下載/抽字幕/擷取畫面後回答內容相關問題。

10環境與流程管理

設定 Claude Code 本身的行為、排程與自訂 skill。

loop

讓某個指令/skill 以固定間隔或自訂步調重複執行。 用於：「每 5 分鐘檢查一次部署狀態」這類需求。

schedule

建立/管理雲端排程 agent（cron 排程任務），含單次定時執行。

update-config

修改 settings.json：權限允許清單、hook、環境變數等。

fewer-permission-prompts

掃描過去操作紀錄，自動整理常用但安全的指令加入白名單，減少每次都要按允許。

keybindings-help

自訂鍵盤快捷鍵/組合鍵。

skill-creator

建立新 skill、優化既有 skill、跑效能評測。

11Claude / Codex 專屬

與 Claude 生態系、Codex 整合、專案理解相關的技能。

claude-api

Claude API / SDK 完整參考：模型 ID、價格、串流、工具呼叫、MCP、快取等，凡是提到 Claude/Anthropic 或 LLM 相關問題都應先查這個，而非憑記憶回答。

codex:rescue

卡關、需要第二意見、或要做深度根因診斷時，把任務交給 Codex 處理。

codex:setup

檢查本機 Codex CLI 是否就緒，並可切換是否要求 review。

graphify

把任何輸入（程式碼、文件、論文、圖片、影片）轉成可查詢的知識圖譜，適合理解整個專案的架構與檔案關聯。

init

幫新專案建立 CLAUDE.md 說明文件。

dot-skill

把某個同事/名人的說話與決策風格蒸餾成可重複使用的 skill 人格。

分類與描述基於目前系統提供的 skill 清單整理，若你常做某一類任務（例如只在意 Google Workspace 或只在意程式碼審查），我可以只保留該類別做成更精簡的版本。
